## Delivered locally

- Expo Router TypeScript app with a clean five-item Summary / History / Track / AI Coach / Profile mobile shell. The raised center Track button opens a native sheet that routes to Food, Water, Blood pressure, Weight, Exercise, or Reminders without adding permanent tab-bar clutter.
- Email/password registration requires first and last name, stores both in Auth metadata and the user-owned public profile, rejects Supabase's empty-identity response for an already-confirmed email instead of showing false success, and retains explicit check-email destinations, login, logout, and SecureStore-backed session restoration. Password recovery now has a real native deep-link handler and new-password screen for both token and PKCE callback forms.
- Profile name editing now distinguishes loaded/saved, unsaved, required, saving, and error states in a persistent inline status panel. The Save name action is disabled and labeled **Name saved** when the trimmed values match storage, then visibly returns to **Save name** as soon as either field changes.
- Signed-in iPhone users can opt into Face ID from one minimal Profile row. Tapping **Enable** opens a compact current-password prompt only for enrollment; the password is revalidated once but never saved. The server issues a random device secret, stores only its SHA-256 hash, and keeps the secret behind Face ID in this iPhone's passcode-required, device-only Keychain. Active Supabase sessions are process-only, so force-quitting returns to the login page instead of silently restoring an authenticated session. The login page has a **Remember me** checkbox that retains only the account identity; an enrolled account additionally exposes the compact Face ID sign-in row after force-quit or explicit local-device sign-out. Backgrounding an active session still shows the privacy gate before health data returns. Disabling Face ID revokes the server credential, and any password change revokes every biometric device credential through a database trigger; the local reset completion message explicitly requires sign-in with the new password and Face ID re-enrollment, while the next attempt on another device removes its stale local enrollment. Legacy Keychain entries containing the previously saved password are deleted rather than migrated. Face ID is unavailable on web/Expo Go and requires the new native development build.
- When Face ID locks the app while the root-level Quick Log sheet is open, the root navigator dismisses that sheet before presenting the gate. Unlocking therefore returns to the previously selected tab instead of leaving Quick Log above the protected content.
- The Face ID privacy gate is intentionally minimal: its tappable Face ID icon and password fallback remain, while the redundant lock title/card are removed. The Progress Photos full-screen header reads the root app inset directly and adds the same 20-point content offset as tab screens, avoiding the Dynamic Island even when the modal SafeAreaView does not receive an inset. Weight History downloads only photo-to-weight metadata and shows a filled photo button with a dot when that entry has uploaded photos.
- Offline SQLite cache and idempotent outbox for manual weight, systolic/diastolic BP, and optional pulse.
- Manual entry form, 30-day visual trends, dashboard snapshot, and explicit sync feedback.
- Reviewed hosted Supabase migration with per-user RLS on profiles and vital samples.
- Hosted training/nutrition migration with per-user RLS for workout sessions/sets, cardio entries, and food entries.
- Muscle-group-first lifting builder (multiple Back, Chest, Tri, Bi, Delt, Legs, Abs selections allowed) with add/remove exercises, blank set-count-driven rep fields, working-weight entry (including a deliberate 0 lb value for bodyweight work), and full prior-session memory.
- Lifting exercises can be reordered with a vertical drag handle before save, the Add exercise action is repeated below the current list, and each workout can persist an optional gym/location value. Workout History editing uses explicit up/down arrow buttons for exercise order. Multi-muscle workouts associate every exercise with a selected muscle group so History can show accurate per-exercise set totals and a count-first sets-by-muscle breakdown. Long breakdowns cannot squeeze the fixed-width, right-aligned session set total against the card edge.
- The app intentionally has no seeded exercises or foods. New suggestions are learned only from completed workouts and saved food entries belonging to the signed-in user; new workout/cardio/nutrition logs start with no selected values.
- Manual cardio logging for walking, running, swimming, tennis, cycling, and other activity types; its form stays compact on Exercise until tapped.
- Manual workout, cardio, weight, blood-pressure, and food history entries are editable. Food-history editing changes the consumed amount/unit and recalculates the immutable nutrition snapshot from its saved serving basis instead of editing nutrition facts. Saving or tapping the custom History back control returns explicitly to the originating History category instead of depending on the navigation stack. Apple Health/imported vital and cardio records remain read-only by design, while imported food snapshots are also protected from mutation.
- Nutrition uses a multi-item meal builder: meal selection comes first, foods can be added/removed like lifting exercises, and suggestions come only from the signed-in user's saved foods. Editing a food already in the unfinished meal is amount/unit-only (amount, unit, and note); its Back/Close action returns directly to the meal and cannot fall into label creation or scanning while retaining the original entry ID.
- Food logging now combines quick entry and saved-food search under **Find or add food**. It searches the user's Recent/My Foods records; selecting a match proceeds with that saved food, while an unmatched name asks whether to create a reusable label and prefills the label name. Every scanned or tracked food automatically creates or reuses a private label in My Foods, including restored legacy drafts and Recent entries that did not previously reference a profile. The Food screen has a dedicated **Manage labels** action; only that manager exposes reusable-label Edit/Delete controls, separating serving/nutrition maintenance from amount logging. Delete uses a centered confirmation overlay and leaves immutable past food history unchanged.
- Reusable labels store calories, protein, carbohydrates, fat, fiber, sugar, sodium, and exact per-serving item, mass, and volume conversions. Users edit one structured **Serving size** section, which requires a positive weight, positive volume, or positive count with a specific physical item unit such as bottle/package/piece; generic `1 serving` and measurement names entered as item units are rejected. The app automatically generates display text such as `1 package (49.6 g)`, `12 pieces (28 g)`, or `1 bottle (14 fl oz)` wherever a combined label is needed, without showing or storing another user-facing field. The legacy/provider serving-label string remains only as an internal display fallback for old data. Changing a weight or volume unit immediately converts the entered value, and the app never guesses food density.
- Barcode lookup runs in an authenticated TypeScript Supabase Edge Function. The camera recognizes EAN-13, EAN-8, UPC-A, and UPC-E automatically; manual entry accepts digits without asking the user to identify the symbology. Before making a provider request, a repeated scan checks the user's normalized barcode labels and immediately reuses the current private profile. This prevents duplicate labels and preserves all saved corrections instead of refreshing over them. New products continue through the identified, cached Open Food Facts resolver and editable package confirmation.
- A barcode that is missing from Open Food Facts now presents an explicit **Create food profile** action, carries the scanned barcode into the private label, and learns that profile for future My Foods suggestions.
- Barcode normalization uses the current Open Food Facts v3.6 product endpoint and its structured `nutrition.aggregated_set` / `nutrition.input_sets` data. It checks the documented `result.id`, rejects malformed provider responses, and no longer scrapes knowledge-panel display text or infers a package size that OFF does not provide.
- Package/piece-style servings are first-class conversions. A label such as `1 package (28.3 g)` defaults to one package, while `12 pieces` defaults to 12 pieces and can accurately scale a partial serving. The app never substitutes 100 g for a named package serving that lacks a mass conversion.
- Provider conversions keep weight and volume separate. Structured `100ml` nutrition becomes a 100 mL volume basis, structured `100g` becomes a 100 g mass basis, and explicit bottle/can fluid quantities remain volume-only. Internally inconsistent provider serving sets keep their entered per-serving nutrients but leave serving description/count/mass/volume blank for package confirmation.
- Lookup outcomes are distinct: a documented OFF `product_not_found` response opens a private manual label with the barcode attached; an invalid UPC/EAN stays on the scanner with digit guidance; network, rate-limit, malformed-response, and provider failures stay on the scanner with retry/manual-entry guidance.
- Reusable profiles are idempotent by stable identity: provider foods reuse `user_id + catalog_product_id`, and manual/provider barcode labels reuse `user_id + canonical barcode`. Migration `202609010003_user_food_profile_barcode_dedup.sql` normalizes existing barcodes, repoints historical entries to one keeper before removing redundant profiles, and enforces per-user barcode uniqueness. Barcode-free foods are never merged by name alone; automatic creation reuses a profile only when its full normalized name, brand, source, serving conversions, and nutrition content match.
- Unfinished meals are persisted locally per user through navigation, backgrounding, and app restarts. Meal history retains immutable brand, amount, source, note, and nutrition snapshots, so later label edits cannot change old totals.
- New locally generated IDs are valid UUIDv4 values on every platform, including native runtimes without `crypto.randomUUID`, preventing PostgreSQL UUID insert failures.
- Combined blood-pressure line chart plus clear daily weight, nutrition, and hydration dashboard cards. Summary always combines manual and imported readings while retaining provenance on each record.
- Hydration logging accepts water or other fluids in mL, fl oz, or cups and stores a canonical mL value. Quick water shortcuts include 8, 12, 16, 20, 24, and 40 fl oz. Profile owns the daily water goal, and Summary shows today's fluid-ounce progress.
- Summary includes a calorie calendar with green goal-progress rings for logged days at or under the target and red rings for days over it. Its concise title uses `September 2026 Calories` capitalization, with direct spacing to the weekday row and no explanatory paragraph. Previous/next controls navigate historical months while preventing navigation beyond the current month. Calories and Protein open Food History instead of the logging form; the redundant lift/cardio-today strip is removed.
- Today reloads cached/synced vitals whenever the tab receives focus, so new manual readings appear in its metrics and trend charts.
- Summary greets the signed-in user with `Hi FirstName,` and places `Your daily snapshot` directly beneath. A compact refresh-icon Sync control remains in the top-right with the last-sync timestamp beneath it; an automatic Apple Health sync with nothing new stays quiet instead of displaying a redundant success message.
- Workout History lists every saved session by date and muscle group, with compact per-exercise set/repetition/weight summaries such as `3 x 12, 12, 12 at 45 lb`, a small top-aligned muscle-group badge that stays fixed when an exercise name wraps, count-first sets-by-muscle breakdowns, and notes. User-facing labels expand Bi/Tri/Delt to Bicep/Tricep/Shoulders while preserving the existing stored values.
- Workout History keeps each count and muscle label together as one non-breaking phrase, so a wrapped sets-by-muscle line cannot leave `3` at the end of one line and move `Shoulders` to the next.
- Weight logging can stage one progress photo from the camera or system photo picker and uploads it only after the weight entry is saved. Every Weight History row has a progress-photo icon that opens the private archive, supports horizontal paging, adds more camera/library photos, and deletes the selected photo in place.
- Progress photos are re-encoded without EXIF as JPEG, resized to at most 1440 px, targeted below 900 KB, and rejected above a 2 MB bucket/database ceiling. A database uniqueness constraint enforces at most three photos per user per local day, immutable UUID object paths make uploads retry-safe, signed URLs expire after one hour, and the paged gallery renders only nearby images to contain memory and egress.
- If Supabase reports a storage quota/service restriction (including its documented HTTP 402 response or known quota error codes), both photo-upload surfaces show an explicit storage-full message with deletion/free-space guidance; unrelated upload errors keep their original diagnostic message.
- Lift search ranks matching exercises within the chosen muscle group and shows the strongest session in the past 90 days plus a conservative double-progression cue.
- Exercise search ignores casing and punctuation differences, protects selection from blur/request races, and preserves prior performance recorded at an explicit 0 lb.
- Today shows the precise local time each displayed weight/BP metric was measured and retains the last successful vital sync timestamp across app restarts.
- Summary has D/W/M/6M/Y controls for both weight and blood pressure. These are fixed-duration rolling viewports: 24 hours, 7 days, 30 days, 183 days, and 365 days. Weight and blood-pressure readings are averaged into local calendar buckets to avoid clutter: hourly for D, daily for W/M, Sunday-through-Saturday weekly for 6M, and monthly for Y. Aggregate X coordinates use the exact bucket boundary—hour, local midnight, Sunday, or first of the month—so plotted points align with matching axis divisions instead of drifting according to the readings' original clock times. The time axis divides D every 3 hours, W every day, M every 7 days, 6M every month, and Y every 2 months.
- Blood-pressure History classifies every complete reading as Normal, Elevated, Stage 1 Hypertension, or Stage 2 Hypertension using the higher category triggered by either number. Reading values retain the standard dark text while the category badge supplies the label and color. Summary builds each aggregate BP point as one explicit systolic/diastolic bucket and classifies that exact averaged pair, preventing independently generated timestamps from mispairing a marker. The main BP average includes the `mmHg` unit, while compact point tooltips show only the averaged pair. Systolic points are solid and diastolic points are outlined; the redundant series-style legend is removed while the category-color legend remains.
- Weight and blood-pressure charts use a live continuous horizontal timeline inspired by Omron Connect: drag right for earlier data and left toward the present. There are no page panels, release-time transitions, date snapping, or quantization. Every movement event updates the exact chart start/end timestamps, axes, averages, and connected plotted data while the finger is still down; release simply leaves that precise window in place. Each line includes the adjacent averaged bucket outside either edge and clips its stroke to the plot, so it remains visually connected as points enter and leave without counting or displaying those neighbors as in-range readings. Movement stops at the live present edge. During a recognized horizontal drag, Summary locks vertical scrolling until release or cancellation, and the authenticated shell's competing iOS dismiss gesture is disabled.
- Summary charts use a taller, nearly edge-to-edge plot with timestamp-positioned grid lines and labels, default to the weekly view, and label the inclusive current date instead of the next exclusive midnight. The Weight card's top-right value is the average of the currently displayed range, matching Blood pressure, and the subtitle is only the selected range label such as `Weekly average`. Tapping a point opens a compact box directly above it instead of a large inspector below the graph: D shows the one-hour span, W/M the date, 6M the Sunday-through-Saturday span, and Y the month, each explicitly labeled AVG with its averaged reading. The box fits the wider text line and adds a consistent nine-unit margin on each horizontal side, retaining visible whitespace without returning to a large fixed width. Tapping the same point again closes the box. Each chart derives one padded vertical domain from all loaded readings for that vital, so its scale remains fixed while the horizontal timeline moves instead of jumping between visible windows.
- History cards open an editable workout view. Saving uses an authenticated Supabase function to atomically replace only the current user's workout and sets.
- History is ordered Workout, Food, Blood pressure, and Weight. Workout combines lift sessions and cardio chronologically; Food groups entries by local date and meal with each food's time aligned beside its name, daily calorie/protein/water totals, and individual deletion. The water total uses the same right-aligned type treatment as calories and protein, and hydration-only days also appear. Every day opens a full totals popup for calories, protein, water/fluids, carbohydrates, fat, fiber, sodium, and sugar; nutrients missing from any entry are labeled as incomplete instead of silently counted as zero.
- Every visible History card now opens an in-app, cross-platform deletion sheet. Workout and cardio rows are deleted remotely under RLS; BP/weight records are tombstoned locally and queued for safe remote sync, so they remain deleted when offline.
- Profile's Account card lets existing users add or change their required first and last name. Saving updates both the user-owned `public.profiles` record and Supabase Auth metadata, so the personalized Summary greeting updates without creating a new account.
- Profile is the sole place to set calorie, protein, hydration, weight, and BP targets. A blank protein target automatically uses `0.7 × latest body weight in lb`; Summary displays calorie/protein/water current and goal values inside tappable circular progress rings.
- Saving Profile goals now shows an accessible inline **Goals saved.** confirmation directly beneath the action; changing any goal clears the stale confirmation.
- Every Summary metric formats its target consistently as `Goal: value unit`, including `Goal: 150 lb`, `Goal: 120/80`, and `Goal: 2200 cal`; measurement timestamps remain visible before Weight and BP goals when readings exist.
- BP targets default to 120/80 mmHg for existing profiles that had no saved BP target and for future profiles.
- Exercise has dedicated Lifting and Cardio subsections. Weight and Blood pressure now have separate designated logging pages, while their existing readings remain in the shared, user-owned `vital_samples` timeline for graphs, offline sync, and Apple Health provenance.
- Reminders now schedules local iPhone notifications for named medication, supplement, custom, blood-pressure, and weight routines. A routine supports once, daily, multiple-times-daily, selected-weekday, or weekly timing and can be marked complete for the current local day. Schedules and completion marks are user-scoped on that device; they are not yet cloud-synced across devices. AI Coach remains a non-connected placeholder for future consented, wellness-only data-informed suggestions.
- Workout's Gym location field suggests the signed-in user's recent saved locations as they type, without a shared or seeded location list.
- An unfinished lifting workout is continuously saved as a user-scoped local draft. It restores after navigation, app restart, or backgrounding and clears only after a successful Finish workout save.
- Food History uses the same bordered Delete button and in-app confirmation sheet as the other History sections.
- Summary Weight, Blood pressure, Calories, and Protein cards open their corresponding History view; Water opens hydration logging.
- The Track sheet is a fixed two-column grid ordered Food/Water, Blood Pressure/Weight, and Workout/Reminders.
- Summary no longer repeats a separate goals card; each top metric retains the relevant goal context, while Profile remains the editing surface.
- Expo dev client and EAS are configured for `@jalenwang/healthapp`; the Apple bundle identifier, signing certificate, ad hoc provisioning profile, and development iPhone registration are active.
- Supabase configuration accepts the current `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` name while retaining compatibility with the legacy `EXPO_PUBLIC_SUPABASE_ANON_KEY` name.
- Expo local and EAS Development/Preview/Production environments consistently target the canonical HealthHub Supabase project (`lztqnyejimzuvdxgtext`).
- Read-only Apple Health integration is intentionally limited to one year of weight and paired blood-pressure readings through a permission-gated iOS adapter.
- Apple Health also requests heart-rate read access and imports the closest pulse within two minutes of a paired BP measurement, preferring the same HealthKit source but accommodating source-label differences; that pulse appears on the Blood Pressure History card and is not editable. Existing connected users get one safe one-year BP/pulse backfill on their next sync.
- Apple Health connection lives in Profile. Once connected, Summary automatically includes Apple Health in its foreground sync whenever the tab opens; Summary's single Sync now control forces the same combined sync on demand.
- Summary and History refresh data silently when a tab regains focus. Only an intentional pull-down shows the native refresh control, so switching tabs does not visibly shift either screen as if it were reloading.
- W and M chart points are now stable full-calendar-day averages. Moving the continuous viewport changes only whether a date is shown and where it sits, never the calculation for that date as readings cross a viewport edge.
- Chart lines preserve each adjacent off-screen bucket's true timeline position before the plot clips it. The visible segment therefore keeps its angle continuously as the window moves rather than pivoting at a chart edge.
- HealthKit imports use per-user deterministic IDs and locally persisted anchors for idempotent incremental sync; imported deletions and user-hidden records are reconciled safely.
- HealthKit source app/device names flow through Supabase and History; meaningless bridge labels such as `SourceProxy` are suppressed. Summary deduplicates an identical manual/imported reading within five minutes for combined charts and averages, while History retains both source records.
- Authenticated tab screens no longer reserve an empty native header. Summary and History explicitly opt out of iOS automatic ScrollView inset adjustment, then apply a stable safe-area top inset so they align with the other tabs without a header-sized gap returning after navigation. The shared tab scene uses the same background as every page, including the status-bar area.
- Removed redundant explanatory subtext across authentication, Food, Workout, History, Water, manual vitals, placeholders, and the Face ID privacy gate. Functional empty states, permission/privacy notices, validation feedback, units, and destructive-action warnings remain where they prevent ambiguity or data loss.
